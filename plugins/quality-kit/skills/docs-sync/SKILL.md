# Bring the docs in line with the change

`qk` says which docs a change owes. You work out what the change means for a reader, and write that or say it means nothing. Reference facts come from a generator or from the code, never from you.

## 1. Get the findings

```sh
qk check --full --format claude
```

`--full` runs the generators, so leave the files alone until it returns. Two kinds of finding are yours:

- **QK020** names a generated file and the command that writes it.
- **QK010** names a changed file and the docs expected to change with it.

When there are no such findings and the user asked for docs, treat each changed file as a QK010 finding. Find its docs by searching the docs folder for the names the change touches.

## 2. Read the change

The change is everything since the branch left the default branch, committed or not. For each file a finding names:

```sh
git diff "$(git merge-base <default branch> HEAD)" -- <file>
```

Done when you can say, for each file, what is different for someone using the system.

## 3. Handle each finding

Take the first line that fits. [references/what-to-write.md](references/what-to-write.md) has the test for "a reader would notice" and how to write each kind of page.

1. **The doc is generated.** QK020 names it, `quality.yaml` lists it under `generated`, or it opens with a `generated by` line. Run its command from the repository root. The file is the command's to write: your Edit and Write stay off it.
2. **A reader would notice nothing.** Write no docs. Propose the no-docs note, as section 4 says.
3. **A reader would notice.** Update the how-to or explanation the finding expects, or write the page if none covers it.

Then look for **tutorials** that walk through what changed, mapped or not. Leave their steps as they are and mark each one for a re-run, as the reference says.

Done when every finding has a generator run, a doc change, or a proposed note.

## 4. Propose the no-docs note

The note is a person's to approve. Give them one sentence on why a reader notices nothing, and the command:

```sh
qk docs-impact none --reason "<that sentence>" --approved-by <their name>
```

Run it yourself only after they have said yes in this conversation and told you the name. Until then the finding stays open. If the Stop hook sends you back for it, give the proposal again in full and stop.

## 5. Check again and report

Run `qk check --full --format claude` again when a generator ran, and `qk check --format claude` otherwise. Report:

1. For each finding: what you did, and the part of the diff it rests on.
2. Tutorials you marked.
3. A proposed note that waits for the person, with its command.
4. What `qk check` still reports, as printed.
