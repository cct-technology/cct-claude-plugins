# Update the docs for a change with Claude

The `docs-sync` skill brings the docs in line with what a branch changed. Claude starts it when Quality Kit reports QK010 or QK020, or when you ask.

## Ask for it

In Claude Code, with the Quality Kit plugin enabled, say:

```text
Update the docs for this change.
```

You can also run `/quality-kit:docs-sync`.

## What Claude does

1. **Gets the findings** with `qk check --full --format claude`. This runs your generators, so it can take a while. Leave the files alone until it returns.
2. **Reads the change**: everything since the branch left the default branch, committed or not.
3. **Handles each finding** in one of three ways:

   | The finding | What Claude does |
   | --- | --- |
   | The doc is generated: it is under `generated` in `quality.yaml`, or opens with a `generated by` line | Runs the command that writes it. It never edits the file |
   | A reader would notice the change | Updates the how-to or explanation the finding expects, or writes the page when none covers it |
   | A reader would notice nothing | Writes no docs, and proposes a no-docs note for you to approve |

4. **Marks tutorials** that walk through what changed.
5. **Checks again** and reports: what it did for each finding and which part of the diff that rests on, the tutorials it marked, a note that waits for you, and what `qk check` still says.

When `qk check` has no docs findings and you ask anyway, Claude searches the docs for the names the change touches and treats those pages the same way.

## Tutorials are marked, not rewritten

A tutorial is worth trusting only after someone has run its steps, and Claude cannot run them. So it leaves the steps and puts a mark under the title:

```markdown
> **Re-run needed:** the invite form now asks for a required **Role**. The steps below may no longer match.
```

Run the tutorial, correct its steps, and delete the mark. To list the tutorials that wait:

```sh
grep -rn "Re-run needed" docs/tutorials
```

## When the change needs no docs

For a refactor that a reader cannot notice, Claude writes nothing. It gives you one sentence on why, and the command:

```sh
qk docs-impact none --reason "Moves the retry loop into withRetry; requests are sent and retried exactly as before." --approved-by <your name>
```

Approve it in one of two ways:

- Reply yes with the name to record. Claude runs the command, and Claude Code asks you once more before it does.
- Run the command yourself.

Until then QK010 stays open. Claude does not approve its own note. If you think a reader would notice after all, say what they would notice, and Claude updates the docs instead. See [When a change needs no docs](keep-docs-in-step.md#when-a-change-needs-no-docs).

## A reference page without a generator

Reference pages should come from the code. When a mapped reference page is written by hand, Claude changes only the facts the diff changed, copied from the code, and tells you the page has no generator. To stop it going stale again, [list it under `generated`](keep-docs-in-step.md#keep-generated-docs-current).
